## 决策框架

1. 产品范围、数值、装备、Boss 和技术架构以 PRD 为准。
2. Web GUI 的视觉语言、布局、交互、组件状态和 UI 验收以 `UI-UX-设计规范.md` 为准。
3. 课程顺序和通用教学约定以 README 为准；具体知识讲解以对应分章文件为准。
4. 合并总览是派生的早期浏览稿，不再承担发布源职责。
5. 可以由公式、可执行代码或现有范围直接判断的冲突自动解决；不通过新增未授权功能来掩盖缺口。
6. “计划实现”和“仓库已经实现”必须分开描述。

## 后续确认的 UI/UX 基线

2026-07-16 在功能文档完成对齐后，又确认了 Web GUI 方向。完整规范见 [UI-UX-设计规范.md](UI-UX-设计规范.md)，其中的核心结论为：

- 产品提供浏览器 GUI，不是面向学员的 CLI。
- 信息架构采用现代学习工具，全界面使用原创 16-bit 像素风。
- 游戏 UI 字体像素化；学习正文和代码为已确认的可读性例外。
- 世界地图是 17 节点分区路线图；章节页是 42/58 学习/代码双栏。
- 章节左栏不是整篇文档阅读器，而是固定舞台与独立滚动叙事信息流；支持逐段/逐字推进、五类发言样式、标题转场、本章回顾和下一章入口。
- Phase 1 使用统一深色主题，动效以像素帧动画和克制状态反馈为主。

## 关键公式复核

- 17 章基础经验合计：`(1 + 17) × 17 ÷ 2 × 100 = 15300`
- 10 场 Boss 经验：`10 × 200 = 2000`
- 通关总经验：`15300 + 2000 = 17300`
- 到达 LV 13 的累计门槛：`(1 + 12) × 12 ÷ 2 × 200 = 15600`
- 通关后等级进度：`17300 - 15600 = 1700/2600`
- 前 10 章章节金币：`(1 + 10) × 10 ÷ 2 × 50 = 2750`
- 前 10 章 5 场 Boss 金币：`5 × 300 = 1500`
- 购买 TRUE 之剑与 FALSE 之盾：`80 + 120 = 200`
- 第 10 章示例余额：`2750 + 1500 - 200 = 4050`

## 后续维护规则

- 修改产品数值或范围时先改 PRD，再同步引用该事实的分章文档。
- 修改 Web GUI 的视觉、布局或交互基线时先改 `UI-UX-设计规范.md`，再同步 PRD 中的概要描述。
- 新增或完成 Boss 内容时，同时更新 README 当前状态和 PRD Phase 2 清单。
- 合并总览只做阶段性同步，不在其中独立定义产品事实。
- 每次文档变更至少运行相对链接、Markdown 围栏、Python 代码块语法和关键数值公式检查。
