# Python 勇者斗恶龙 UI/UX 设计规范

> 版本：v1.0 | 日期：2026-07-16 | 状态：核心方向已确认

---

## 1. 文档职责

本文档是 Web 学习平台的视觉、布局、交互和可访问性规范，用于指导设计、前端实现与 UI 验收。

- 产品范围、功能优先级、游戏数值和技术架构以 [PRD-Python-DragonQuest.md](PRD-Python-DragonQuest.md) 为准。
- 视觉语言、页面布局、组件状态和交互验收以本文档为准。
- 本项目明确提供浏览器 GUI。CLI 仅用于开发、构建和运维，学员不需要使用终端。

## 2. 体验目标

目标用户是零基础 Python 学员，主要在桌面浏览器中连续学习 30-60 分钟。GUI 必须同时满足：

1. **一眼看懂**：学习目标、当前任务和下一步操作始终清楚。
2. **随时动手**：学员可以在阅读讲解的同时查看、编辑和运行代码。
3. **冒险有感**：地图、角色、奖励和 Boss 战持续提供进度感。
4. **克制游戏化**：像素风服务于学习，不用装饰、动画或声效干扰代码阅读。

## 3. 核心设计方向

### 3.1 设计定义

**现代学习工具的信息架构 + 全界面 16-bit 像素视觉语言。**

- 视觉上：经典俯视角奇幻冒险氛围约 60%，亲和清晰的掌机 RPG 界面约 40%。
- 操作上：保持现代 Web 产品的即时反馈、键盘可达、明确错误和低学习成本。
- 美术参考可来自经典 16-bit 冒险与怪物收集 RPG，但必须使用原创角色、地图、符号、精灵图、字体和界面构图。

### 3.2 像素语言

- 所有游戏界面使用整数网格、硬边界、阶梯轮廓和有限阴影层级。
- 面板和按钮默认为直角，不使用圆润 SaaS 卡片、玻璃拟态或模糊背景。
- 界面图标、装备、奖励、地图地块和角色头像使用原创像素素材。
- 不将现有商业游戏中的角色、标志性道具、Logo、地图或精灵图用于产品。

### 3.3 视觉密度

- 布局变化度：5/10，允许地图和奖励场景更自由，学习页保持稳定。
- 动效强度：4/10，以状态反馈和逐帧演出为主。
- 信息密度：6/10，同屏支持阅读与编码，但避免驾驶舱式堆叠。

## 4. 颜色与形状系统

### 4.1 默认主题

Phase 1 只实现统一深色主题。浅色主题不进入 MVP，后续可在不修改语义令牌的前提下扩展。

| 语义令牌 | 建议值 | 用途 |
| --- | --- | --- |
| `canvas` | `#0B1020` | 页面与地图底色 |
| `surface` | `#17233A` | 主面板、HUD、对话框 |
| `surface-raised` | `#22324D` | 选中面板、悬浮层 |
| `border-dark` | `#07101D` | 像素外边框和硬阴影 |
| `border-light` | `#53698B` | 内高光和焦点边界 |
| `text` | `#F2EAD3` | 主文字 |
| `text-muted` | `#AAB6C8` | 次要说明 |
| `accent` | `#D6A84B` | 主操作、当前关卡、奖励 |
| `accent-pressed` | `#A97828` | 主按钮按下状态 |
| `success` | `#4E9F65` | 通过、完成 |
| `error` | `#C85B5B` | 错误、失败 |
| `info` | `#4F83C2` | 中性提示 |
| `locked` | `#697386` | 锁定内容 |

暖金是唯一主强调色。成功、错误和信息色只用于实际状态，不作为装饰。各地图区域可使用低饱和环境色，但不改变全局面板主题。

### 4.2 形状与间距

- 圆角：默认 `0`，仅允许地图上的自然地形轮廓使用不规则边缘。
- 边框：使用 2px 或 4px 像素边框，不使用半透明模糊描边。
- 阴影：使用 2px 或 4px 整数位移的硬阴影，不使用大范围柔化投影。
- 间距：以 4px 为基础网格，常用间距为 8/12/16/24/32px。
- 点击目标：可交互区域至少 40×40px，不因像素图标尺寸缩小操作范围。

## 5. 字体系统

### 5.1 字体分层

| 内容 | 字体要求 | 典型位置 |
| --- | --- | --- |
| 游戏界面 | 支持简体中文的像素字体 | 顶部导航、HUD、地图、按钮、弹窗、剧情对话、角色面板、商店、Boss 战、奖励和状态标签 |
| 学习正文 | 高可读中文无衬线字体 | 知识讲解、较长的任务说明、错误解释 |
| 代码 | 高可读等宽字体 | Monaco、代码块、沙箱输出 |

像素风是游戏界面字体的必选要求。实现统一使用 Fusion Pixel Font 12px 比例模式简体中文版（上游版本 `2026.07.01`，SIL OFL 1.1），并从 `public/fonts/fusion-pixel/` 自托管。学习正文和代码是已确认的可读性例外，但它们所在的容器仍须遵循像素边框、颜色和阴影系统。

### 5.2 排版约束

- 游戏 UI 正文不小于 16px，主按钮不小于 16px，页面标题建议 24/32px。
- 学习正文默认 16px，行高 1.7-1.8，单行建议不超过 72 个中文全角字符宽度。
- 代码默认 14px，允许学员在 12-20px 范围内调整。
- 字号、行高和字体加载不得依赖分数缩放，避免像素边缘发虚。
- 最终中文像素字体必须支持产品所需字符集、WOFF2 自托管、`font-display: swap` 和可商用许可，上线前必须完成字形缺失测试。

## 6. 全局布局与导航

### 6.1 桌面基线

- Phase 1 支持宽度为 1024px 及以上的桌面浏览器。
- 页面主内容最大宽度建议 1440px，两侧至少保留 24px 安全边距。
- 顶部导航默认高度 56px，1024px 宽度下仍必须单行显示。

### 6.2 顶部导航

| 区域 | 内容 |
| --- | --- |
| 左侧 | 原创品牌标识，进入章节后同时提供返回世界地图 |
| 中部 | 地图、角色、商店、排行榜 |
| 右侧 | 等级、金币、连续学习天数、角色头像 |

章节页进入专注模式，导航降低视觉权重，但不隐藏返回地图、存档状态和角色状态。AI 魔法书使用右下角悬浮入口，不占用主导航位置。

## 7. 核心页面

### 7.1 首次进入与角色创建

- 无本地存档时，首页显示简短产品介绍与单一主操作「开始冒险」。
- 角色创建只要求姓名和 10 个原创像素头像之一，不在 MVP 强制登录。
- 姓名字段必须有可见标签、字数提示、内联错误和明确焦点状态。

### 7.2 世界地图

- 采用分区式冒险路线图，17 个关卡按主题区域组织，通过一条连续路线连接。
- 地图是可导航的关卡选择界面，不实现自由行走或独立地图引擎。
- 已通关节点为金色，当前节点使用轻微脉冲，未解锁节点为灰色并附带锁图标。状态不得只依赖颜色。
- 点击节点先打开关卡卡片，显示章节、学习目标、奖励、完成状态和「开始任务」，不直接跳转。
- 提供等价文字列表入口，供键盘用户、辅助技术和窄屏使用。

### 7.3 章节学习页

1. 进入关卡时先显示简短剧情任务卡。
2. 点击「开始任务」后进入左右双栏学习界面。
3. 左侧约 42%，按「目标 → 讲解 → 示例 → 挑战」渐进展开，允许返回查看。
4. 右侧约 58%，放置粘性 Monaco 编辑器、运行操作和结果面板。
5. 编辑器始终可用，不强制学员读完全部文字才能写代码。
6. 运行失败时先显示清晰错误与可选分级提示；运行成功时显示短反馈、奖励和下一步。

在 1024px 宽度下不得出现整页水平滚动。双栏之间使用可拖拽分隔条属于 Phase 4 增强，不是 MVP 前置条件。

### 7.4 Boss 战

- 沿用章节学习页的信息架构，不另建一套代码挑战系统。
- 剧情对话、Boss 精灵图、属性面板和奖励结算可提高沉浸度，但挑战题、编辑器和测试结果仍使用通用组件。
- 对话选项支持方向键、Enter、鼠标和触控板，选择后保持明确焦点。

### 7.5 角色、商店与排行榜

- 角色页将属性、装备槽、背包和成就分组，数字使用等宽对齐或等宽数字形。
- 商店页默认按解锁与可购买状态分组，购买前显示属性变化与余额，购买后给出可撤销或确认反馈。
- 排行榜属于 Phase 3 P2，显示全局榜和周榜，当前用户所在行必须有非颜色标识。

## 8. AI 魔法书

- Phase 3 以右下角悬浮按钮作为入口，打开 360-400px 的右侧抽屉。
- 抽屉在桌面端覆盖页面，不突然改变章节双栏比例；关闭后焦点返回触发按钮。
- 练习失败时可显示非阻塞建议，自动打开必须可在设置中关闭。
- 辅导模式不直接给出当前练习的完整答案；协作模式可提供示例，但要求学员运行与验证。
- 抽屉支持 Escape 关闭、焦点约束、对话记录滚动与明确的生成中/失败/重试状态。

## 9. 组件与状态

### 9.1 通用状态

所有交互组件至少实现：默认、悬浮、键盘焦点、按下、禁用、加载和错误状态。

- 按下反馈使用 1-2px 整数位移、颜色切换和硬阴影收缩。
- 键盘焦点使用至少 2px 的高对比外框，不与悬浮状态混用。
- 核心结果使用页面内联状态，Toast 仅用于「已复制」一类短暂且非核心的反馈。

### 9.2 代码运行状态

| 状态 | 必须显示的信息 |
| --- | --- |
| 待运行 | 题目目标、「运行代码」、快捷键 |
| 运行中 | 已提交、可取消与超时上限，防止重复提交 |
| 通过 | 通过的测试数、奖励与下一步 |
| 未通过 | 失败测试、期望与实际差异、可选提示 |
| 运行错误 | 错误类型、可定位行号、初学者可理解的解释 |
| 超时/服务失败 | 超时或服务状态、重试操作，不判定为学员答错 |

### 9.3 页面状态

- 加载：使用与最终布局形状一致的像素骨架，避免整页中央无上下文转圈。
- 空状态：说明为什么暂无内容，并给出可执行的下一步。
- 错误：在发生位置显示原因、影响和恢复操作，不只显示「出错了」。
- 存档：自动保存需显示「保存中/已保存/保存失败」，导入前显示将覆盖的进度概要。

## 10. 动效与声效

- 角色、地图路径、宝箱和胜利效果使用逐帧像素动画。
- 按钮和状态切换使用 80-160ms 短反馈，面板进出使用 160-240ms，奖励演出原则上不超过 800ms。
- 页面切换可使用快速擦除、像素溶解或格栅揭示，不使用大量平滑漂浮。
- 当前地图节点可循环呼吸，其他无信息价值的永久动画禁用。
- Boss 战屏幕震动限制在 2px 位移和 120ms 左右，不影响编辑器，并允许关闭。
- 声效用于按下、解锁、成功和 Boss 演出；默认音量克制，提供全局静音。
- 所有非必要动画必须遵循 `prefers-reduced-motion`，降级为静态、瞬时切换或非位移反馈。

## 11. 响应式策略

| 宽度 | 策略 |
| --- | --- |
| ≥ 1280px | 完整双栏章节页，地图显示全部区域与关卡卡片 |
| 1024-1279px | 保留 42/58 双栏，压缩次要 HUD 文字，不隐藏核心操作 |
| 768-1023px | Phase 4：章节页切换为「课程/代码」双标签，地图提供分区切换和文字列表 |
| < 768px | Phase 4：单栏页面，代码编辑器独立全屏打开，所有关卡保留文字列表入口 |

Phase 1 不声称支持 1024px 以下屏幕，但实现时不得使用会阻碍 Phase 4 降级的固定像素定位。

## 12. 可访问性

- 正文与背景对比度至少达到 WCAG AA；大字不得借用像素轮廓掩盖对比不足。
- 页面需要清晰的标题层级、语义化区域和「跳到主内容」链接。
- 所有主要操作、地图节点、对话选项、弹窗和抽屉支持键盘完成。
- 颜色不是状态的唯一信号，同时提供图标、文字或形状变化。
- 重要图像提供替代文本，装饰像素素材对辅助技术隐藏。
- 在 200% 浏览器缩放下，核心任务仍可完成，不丢失运行、保存或返回地图操作。

## 13. 实现约束

- Tailwind CSS 负责语义令牌、网格和响应式；交互优先使用原生按钮、链接、输入和语义区域。只有出现复杂弹窗、抽屉或组合控件时，才评估引入无样式可访问组件基础。
- Monaco 保留标准编辑能力，仅定制主题、外框、行号区、工具栏和结果面板，不使用 CSS 破坏选区、光标或辅助功能。
- 独立低分辨率像素图优先按整数倍缩放；高分辨率网格图集允许通过 SVG `viewBox` 等比裁切到约定展示尺寸。两者都必须保持正确宽高比并启用 `image-rendering: pixelated`。
- Phase 1 固定使用 `public/assets/art-v2/` 下的欧洲奇幻主题；头像、Boss、装备、GUI 图标与地图状态节点从稳定网格图集按坐标裁切，不提供运行时皮肤切换。中式图集保持同构并纳入合同检查，留待后续主题状态落地。旧 `public/assets/ui/` 几何切片只作兼容保留，不再进入当前页面依赖。
- 动效只改变 `transform` 和 `opacity`，避免逐帧修改布局属性。
- 图标系统使用统一的原创像素图集，不在同一界面混用 emoji、线性图标和像素图标。
- 层级只使用预定义的 z-index 令牌，至少包含基础内容、粘性导航、悬浮助手、抽屉、弹窗和全局通知。

## 14. UI 验收清单

一个页面只有同时满足下列条件才能进入完成状态：

- [ ] 游戏界面、导航、HUD、按钮和对话使用像素字体；学习正文和代码按已确认的例外处理。
- [ ] 未出现无规则圆角、柔化阴影、模糊背景、玻璃拟态或无语义渐变。
- [ ] 1024px 宽度下导航单行、核心操作可见、页面无水平滚动。
- [ ] 章节页在桌面端符合 42/58 双栏，编辑器可在阅读时持续使用。
- [ ] 地图具备 17 个节点、分区路线、完成/当前/锁定状态与文字列表入口。
- [ ] 所有按钮、输入、节点、弹窗和抽屉具备键盘焦点与完整状态。
- [ ] 加载、空内容、错误、超时、成功、保存失败和重试均有明确界面。
- [ ] 文字对比、键盘路径、替代文本、减少动效和 200% 缩放已验证。
- [ ] 所有像素素材和字体的来源、许可和字符覆盖已记录，不包含可识别的商业游戏资产。

## 15. 已确认决策

| 决策 | 结论 |
| --- | --- |
| 产品形态 | 浏览器 GUI，不是面向学员的 CLI |
| 信息架构 | 现代学习工具 |
| 整体风格 | 全界面 16-bit 像素风 |
| 风格比例 | 俯视角奇幻冒险 60%，亲和掌机 RPG 界面 40% |
| 知识产权边界 | 只借鉴风格类型，不复制现有 IP 资产 |
| 主题 | Phase 1 统一深色主题 |
| 字体 | 游戏 UI 像素字体；学习正文高可读字体；代码等宽字体 |
| 全局导航 | 56px 顶部导航 + 右下 AI 入口 |
| 世界地图 | 17 节点分区冒险路线图，不实现自由行走 |
| 章节布局 | 左侧 42% 学习内容，右侧 58% 粘性代码区 |
| 章节流程 | 剧情任务卡 → 目标/讲解/示例/挑战 → 结果与奖励 |
| 动效 | 像素帧动画 + 克制反馈，支持减少动效 |

上表中的决策不得在实现中静默改变。如需调整，先更新本文档并记录决策原因。
