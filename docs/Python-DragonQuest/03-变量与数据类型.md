## 核心讲解

### 变量为什么更像名册中的名字，而不是装数据的盒子

#### 有局限的比喻：变量是装数据的盒子

很多人第一次学变量时，会听到这样的解释：

```markdown
HP 是一个盒子，把 100 装进去
```

如果你说：「`hp = 100` 是装进去，`hp = 85` 就把 100 换成 85。」这个说法能帮助预测简单代码的输出。但它容易让人误以为赋值会复制对象，也解释不了几个关键场景：

> **选读预览**：下面三个场景会提前出现列表和函数，它们分别在第 10 课和第 8 课正式讲解。现在只需观察输出、理解「多个名字可以指向同一个对象」，不要求独立写出这些代码。

##### 场景一：多个变量指向同一个对象

```python
a = 100
b = a                       # b 绑定到 a 当前指向的同一个对象
print(f"初始：a = {a}, b = {b}")

a = 200                     # 只重新绑定名字 a
print(f"更新后：a = {a}, b = {b}")
```

第二行输出是 `更新后：a = 200, b = 100`。重新绑定 `a` 不会重新绑定 `b`。

这个案例看起来也可以套进盒子比喻：仿佛赋值时复制了一份内容。但下一个案例会暴露问题。

[实践检查点: binding-reassignment/output]
运行右侧代码，确认更新后 `a` 是 200、`b` 仍是 100，然后继续。

##### 场景二：可变对象（列表）的共享修改

```python
背包a = ["手机", "钱包", "钥匙"]
背包b = 背包a                           # 普通赋值不会复制这个列表对象
print(f"初始：背包a = {背包a}")
print(f"初始：背包b = {背包b}")

背包a[0] = "身份证"                     # 修改两个名字共同指向的列表
print(f"修改后：背包a = {背包a}")
print(f"修改后：背包b = {背包b}")
```

输出是 `['身份证', '钱包', '钥匙']`。两个变量指向的是同一个列表，所以从任一变量修改列表，另一个变量看到的内容也会变化。

[实践检查点: shared-list/output]
运行右侧代码，确认修改后 `背包a` 和 `背包b` 都包含「身份证」，然后继续。

公会名册模型可以同时解释两个场景：

```text
当前作用域的名册
a ──┐
    ├──> 同一个列表对象
b ──┘
```

执行 `a = "铁剑"` 是更新名册中 `a` 的绑定；执行 `a[0] = "身份证"` 则不是重新绑定名字，而是通过 `a` 找到列表并修改其中一项。

**关键差异**：

- **盒子比喻**：能粗略解释简单赋值，却容易让人误以为 `=` 会复制对象本身。
- **名册比喻**：名字记录在当前作用域的名册里并绑定到对象。`b = a` 不复制对象，只让 `b` 也绑定到 `a` 当前指向的对象。
- **修改与重新绑定不同**：`a = 新值` 更新名字 `a` 的绑定；`a[0] = 新值` 修改列表中的一项。

##### 场景三：函数参数传递

```python
def modify(x):
    x = 1000

a = 100
modify(a)
# a 会变成 1000 吗？
```

实际结果是 `a` 仍为 100。调用函数时，参数名 `x` 会在函数自己的局部名册中绑定到传入的对象；`x = 1000` 只更新这个局部名字，不会重新绑定调用方的 `a`。

但函数可以修改共享的可变对象：

```python
def add_item(items):
    items.append("药水")

bag = []
add_item(bag)
print(bag)  # ["药水"]
```

这里 `items` 和 `bag` 找到的是同一个列表。函数没有重新绑定 `bag`，而是修改了共享列表，所以调用方能看到变化。

**为什么名册模型能解释这些？**

在 Python 里，程序中的数据由对象表示。数字 `100` 是整数对象，字符串 `"勇者刘老三"` 是字符串对象。

变量名不是对象本身。名字存在于命名空间中，并绑定到对象；不同作用域可以各有一份同名记录。

#### 更准确的比喻：名字登记在公会名册中

```python
hp = 100        # 在当前名册中，让名字 hp 绑定到整数对象
mp = 50         # 在当前名册中，让名字 mp 绑定到整数对象
```

以后使用名字 `hp`，Python 会按照作用域规则查找它当前绑定的对象。

这个入门模型抓住了三个重点：

1. **先计算右侧**——`hp = 85` 会先计算右侧表达式，得到一个结果对象
2. **再更新绑定**——当前名册中的名字 `hp` 改为绑定到这个结果对象
3. **赋值不等于复制对象**——`b = a` 让两个名字绑定到同一个对象，普通赋值不会复制这个对象

> **模型边界**：标签只是帮助理解的图像，标签信息不是真的保存在对象身上。简单名字赋值会更新绑定；`bag[0] = ...` 和 `hero.hp = ...` 则是在修改元素或属性。旧对象是否仍留在内存中属于 Python 实现细节，不应依赖。

### 变量操作——建立绑定、查找名字、重新绑定

```python
# === 建立绑定 ===
hp = 100        # 名字 hp 绑定到右侧求值得到的整数对象
mp = 50         # 名字 mp 绑定到右侧求值得到的整数对象
name = "刘老三"  # 名字 name 绑定到字符串对象

# === 查找名字 ===
print(hp)       # 查找 hp 当前绑定的对象，输出 100

# === 重新绑定 ===
hp = 85         # 先求出右侧结果，再让 hp 绑定到它
# 以后读取 hp 得到 85；旧对象是否继续存在是实现细节

# === 多个名字绑定到同一个对象 ===
a = 100
b = a           # 取得 a 指向的对象，让 b 也绑定到它

# === 只重新绑定其中一个名字 ===
a = 200
# 以后读取 a 得到 200，读取 b 仍得到 100
```

**逐行解读**：

- `hp = 100` —— Python 先计算右侧表达式，再在当前作用域中让名字 `hp` 绑定到结果对象。
- `mp = 50` —— 同理，名字 `mp` 绑定到右侧求值得到的整数对象。
- `hp = 85` —— 更新名字 `hp` 的绑定；这不会把整数 100 修改成 85。
- `a = 100`；`b = a` —— 读取 `a` 得到它绑定的对象，再让 `b` 绑定到同一个对象。
- `a = 200` —— 只重新绑定 `a`；`b` 的绑定没有变化，所以读取 `b` 仍得到 100。

**关键理解**：`b = a` 会先取得 `a` 当前绑定的对象，再让 `b` 绑定到同一个对象；普通赋值不会复制这个对象。

**冒险类比**：

- **登记名字**——公会名册把代号【三尺剑】登记为指向某件装备
- **更新记录**——把【三尺剑】改为指向另一件装备，只改变这条记录
- **多条记录指向同一对象**——你和队友的目标代号都可以指向同一只史莱姆
- **名册有作用域**——队伍名册和世界名册可以各自拥有同名记录，Python 会按作用域规则查找

### 数字类型——整数与浮点数

```python
hp = 100            # int（整数）——生命值，只有整点
crit_rate = 0.15    # float（浮点数）——暴击率 15%

# 向下取整除法：100 金币，恢复药 30 一瓶，最多买几瓶？
max_potions = 100 // 30   # → 3（结果向下取整）

# 普通除法即使整除也会得到 float
average_damage = 30 / 2   # → 15.0

# 属性倍率使用乘法
base_damage = 10
boosted_damage = base_damage * 1.5   # → 15.0
```

**逐行解读**：

- `hp = 100` —— 100 是整数（`int`）。本游戏把 HP 设计为整数，没有「半滴血」。
- `crit_rate = 0.15` —— 0.15 是浮点数（`float`）。浮点数常用于表示暴击率和属性倍率等带小数的数。
- `100 // 30` —— `//` 是向下取整除法。正数例子中结果是 3，表示最多买 3 瓶；遇到负数时也始终向更小的整数取整，例如 `-5 // 2` 是 `-3`。
- `30 / 2` —— `/` 是普通除法，即使刚好除尽也会得到 `15.0` 这样的 `float`。
- `base_damage * 1.5` —— `*` 是乘法。整数乘浮点数后，这里得到 `15.0`。

| 类型            | 冒险例子           | 说明                                  |
| --------------- | ------------------ | ------------------------------------- |
| `int`（整数）   | `hp = 100`         | 生命值，只有整点                      |
| `float`（浮点数） | `crit_rate = 0.15` | 暴击率 15%                          |
| `//` 向下取整除 | `100 // 30 = 3`    | 商向下取整；正数场景可算最多买几瓶    |
| `/` 普通除法    | `30 / 2 = 15.0`    | 即使整除，结果通常也是 `float`         |

**冒险思维**：本章先学习最常用的两种数字类型——整数 `int`（等级、HP、金币数）和浮点数 `float`（暴击率、属性倍率）。Python 还有其他数字类型，后续需要时再认识。

### 字符串类型——角色的名字与称号

```python
hero_name = "勇者刘老三"
title = "史莱姆克星"
full_title = hero_name + "·" + title   # → "勇者刘老三·史莱姆克星"

divider = "=" * 30   # → "=============================="
```

**逐行解读**：

- `hero_name = "勇者刘老三"` —— 字符串（`str`）用引号括起来。单引号 `'...'` 或双引号 `"..."` 都可以，但要配对。
- `title = "史莱姆克星"` —— 另一个字符串。干掉一只怪物 → 获得称号。
- `hero_name + "·" + title` —— 字符串用 `+` 拼接。注意中间的 `"·"` 也是字符串——一个字一个字粘起来。
- `"=" * 30` —— 字符串用 `*` 重复。`"="` 这个字符重复 30 次，等于画了一条分隔线。

**冒险类比**：称号系统。干掉一只怪物 → 获得称号 → 拼在名字后面。杂货铺招牌上画分隔线，`"=" * 30` 就是画线。

### 布尔类型与 None——「是/否」与「值的缺失」

```python
is_alive = True           # 还活着
has_weapon = False        # 手无寸铁
is_stunned = False        # 没被眩晕

quest_item = None         # 当前没有任务物品
```

**逐行解读**：

- `is_alive = True` —— 布尔类型（`bool`），只有 `True` 和 `False` 两个值。注意大写开头。
- `has_weapon = False` —— `False` 表示「否」。勇者出门忘带武器。
- `is_stunned = False` —— 眩晕状态。这些布尔值后面会在 `if` 语句中用（第 5 课）。
- `quest_item = None` —— `None` 表示值的缺失。它不同于 `0`、空字符串 `""`、空列表 `[]` 和 `False`。

**冒险类比**：勇者状态栏用 `True` / `False` 表示真假状态。任务系统可以约定 `quest_item is None` 表示「尚未获得任务物品」，也可以在别的程序里表示「没有提供」「尚未计算」等；「尚未获得」是游戏赋予它的业务含义，不是 `None` 自带的唯一含义。

## AI 协作指南

### 场景一：让 AI 帮你理解类型错误

当你写代码时把类型搞混了，AI 是最好的纠错伙伴：

> **Prompt 示例**：「我在写 Python 代码时遇到这个错误：`TypeError: can only concatenate str (not "int") to str`。我的代码是 `print("HP:" + 100)`。帮我解释为什么错，以及应该怎么改。」

AI 会告诉你：`"HP:"` 是字符串，`100` 是整数，不能直接用 `+` 拼接。应该用 f-string：`print(f"HP:{100}")` 或转成字符串：`print("HP:" + str(100))`。

### 场景二：用 AI 检查变量命名和设计

创建角色属性时，让 AI 帮你审查设计：

> **Prompt 示例**：「我正在用 Python 做一个 RPG 游戏的角色系统。目前我设计了这些变量：`hp = 100`、`mp = 50`、`atk = 15`、`def = 10`。请帮我检查：（1）有没有漏掉重要的属性？（2）`def` 作为变量名有没有问题？（3）还有哪些属性应该加进来？」

AI 会发现 `def` 是 Python 的关键字（定义函数用的），不能做变量名，建议改成 `def_stat`。还会建议你加上 `level`、`gold`、`exp`、`max_hp`、`max_mp` 等。
