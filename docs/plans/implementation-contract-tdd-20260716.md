# Python DragonQuest Contract-First + TDD 实施计划

**日期**: 2026-07-16
**产品依据**: `docs/Python-DragonQuest/PRD-Python-DragonQuest.md`
**UI 依据**: `docs/Python-DragonQuest/UI-UX-设计规范.md`
**API 契约**: `contracts/openapi.yaml`
**本地存档契约**: `contracts/game-state.schema.json`

## 1. 本轮完成定义

完成一个可在本地运行的桌面 Web 学习闭环：

1. 创建原创像素勇者并保存到 localStorage。
2. 在 17 节点世界地图上查看完成、当前和锁定状态。
3. 阅读课程 Markdown，在 Monaco 中完成每章的契约练习。
4. 通过独立执行服务运行 Python，依契约返回通过、未通过、错误或超时。
5. 通关后幂等地结算经验、金币、解锁和 Boss 额外奖励。
6. 查看角色、背包和商店，完成购买与装备的本地闭环。

## 2. 明确的外部边界

以下能力已在 PRD 中定义为后续阶段或仍有开放决策，不使用伪数据声称完成：

- Phase 3 内置 AI 魔法书：需要确认供应商并配置 API 凭据。
- Phase 3 邮箱账号、多设备同步与全局排行榜：需要数据库与身份服务。
- 生产代码执行平台：本仓库实现独立执行服务和容器约束，供应商、网络边界和扩缩容在部署阶段决定。

## 3. TDD 顺序

1. 契约测试：OpenAPI 路径、请求/响应必填字段、存档 Schema。
2. 领域测试：17 章目录、解锁、经验、Boss 奖励、幂等通关、购买与装备。
3. 执行测试：输出标准化、通过/失败判定、错误和超时。
4. 路由契约测试：章节列表、章节详情、代码执行边界。
5. 构建与运行时验收：TypeScript、ESLint、Next.js build、HTTP smoke test、桌面 UI 检查。

## 4. 最小实现原则

- 课程 Markdown 直接作为内容源，不新建 CMS。
- 游戏进度使用版本化 JSON 存档，不在 MVP 引入数据库。
- 每章先只维护一个可自动判定的综合练习，课程原文中的其他练习继续作为阅读与自由练习。
- 不为未确认的 AI 供应商、账号系统或二周目预先建抽象。

## 5. 2026-07-16 实施结果

本轮完成了第 1 节定义的本地学习闭环，并通过契约、领域和服务测试。实现中曾出现一版精简装备占位目录；合同复核发现它与 PRD 的 15 件正式装备冲突后，先将 PRD 数量与关键物品写入失败测试，再替换为权威名称、数值、价格和章节门槛。

已完成：

- OpenAPI 3.1 API 契约与严格的本地存档 JSON Schema。
- 17 章目录、单一综合契约练习、地图解锁、幂等结算、等级/金币/Boss 奖励。
- Markdown + Monaco 工作台、stdout/stdin、四态执行结果和 Docker 隔离服务。
- 15 件正式装备、购买/装备/属性叠加、角色与背包页面。
- 存档导出、导入和运行时契约校验。

仍遵循第 2 节外部边界；此外，多组隐藏 Boss 测试、nsjail 双层沙箱、Boss 免费掉落、提示药水和战斗表现保留在 Phase 2，不以当前单一输出契约冒充完成。
